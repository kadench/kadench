## Areas of Focus

### Data & Information Management

Organizing, validating, transforming, and interpreting information. I'm interested in how data is structured, how inconsistencies develop, and how large collections can be made easier to understand and manage.

### Automation & Process Improvement

Finding repetitive or inefficient processes and developing solutions that reduce unnecessary manual work. I prefer automation that remains understandable, maintainable, and practical to use.

### Systems & Infrastructure

Working with interconnected technologies, including self-hosted applications, networking, containerization, DNS, and remote access. I'm interested in how individual components contribute to the reliability and usability of a larger system.

### Development & User Experience

Building applications and utilities around actual use cases. Beyond functionality, I pay attention to how information is presented, how users navigate a tool, and how much effort it takes to accomplish a task.

## Portfolio

Independent projects focused on practical problems, information management, and usable tools.

### [SlickSyntax](https://github.com/kadench/SlickSyntax)

**Text Processing · Pattern Generation · Productivity**

Creating advanced search patterns can be unnecessarily difficult, particularly when different applications use incompatible syntax.

SlickSyntax is a browser-based tool that generates search patterns from example text for Google Docs, Microsoft Word, and Python.

Its functionality includes interactive pattern editing, searchable syntax references, local history, and offline export.

**What it demonstrates:** Translating complex technical functionality into an accessible interface, handling differences between application-specific syntax, and designing tools around productivity.

### [Audio Metadata Auditor](https://github.com/kadench/audio_metadata_auditer)

**Data Validation · File Analysis · Reporting · Python**

Large music libraries can accumulate missing metadata, inconsistent artwork, and organizational problems that become difficult to identify manually.

Audio Metadata Auditor is a command-line utility that scans audio collections, identifies metadata inconsistencies, and generates structured health reports without modifying the original files.

It supports configurable scanning depth, debugging output, and multiple report destinations.

**What it demonstrates:** Data inspection, validation logic, non-destructive processing, and turning detailed findings into understandable reports.

## Homelab & Independent Infrastructure

My personal homelab is an ongoing project that has developed beyond its original [Homelab Showcase](https://github.com/kadench/homelabshowcase).

It serves as a practical environment for experimenting with infrastructure, networking, automation, and service integration.

My work has included:

- Deploying and maintaining self-hosted applications using Docker.
- Configuring Tailscale for private remote connectivity.
- Using Pi-hole DNS and custom aliases to simplify service navigation.
- Making music and audiobook services accessible across local and remote networks.
- Troubleshooting service availability, configuration, and connectivity.
- Developing setup guidance and exploring self-service support for other users.

Unlike a standalone application, this environment requires continuous maintenance and adjustment as services, requirements, and user needs change.

It has also reinforced my interest in the relationship between infrastructure and user experience: a system isn't particularly useful if the people relying on it can't access or understand it.

## How I Work

I generally approach problems by understanding the existing process before deciding what needs to change.

I look for the underlying cause of an inconvenience, the relationships between its components, and whether an existing solution can be adapted before creating something new.

The principles I return to most often are:

- **Understand the problem.** Determine what's actually causing friction rather than treating only its symptoms.
- **Make information useful.** Structure and present data so it supports understanding and decisions.
- **Reduce unnecessary work.** Automate repeatable processes where doing so provides meaningful value.
- **Consider the whole system.** Account for dependencies, integration, usability, and maintenance.
- **Keep improving.** Test assumptions, investigate failures, and refine solutions beyond their initial implementation.
